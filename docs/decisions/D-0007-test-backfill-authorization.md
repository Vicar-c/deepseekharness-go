# D-0007 · 补测试默认授权，不再逐次询问

- **状态**：生效
- **日期**：2026-11-21
- **决策人**：用户
- **关联任务**：[T-0007](../tasks/T-0007-batch0-1-tools.md)
- **关联提交**：`test(builtin)` 与 `docs` 提交
- **取代/被取代**：—

## 背景

批次 0+1 交付后，用户要求逐点确认"是否达成目标、是否都做了测试"。复查发现 6 个测试盲区（流水线路径、`working_directory` 对 shell、工具上限与过滤、`read_image` 大图分支、`edit` 权限、`staticcheck`/`build.ps1` 未跑），补测时又发现两条既有欠账（shell 超时、guard 拒绝）。我询问是否补这两条，用户指示：

> "这种补上测试的不要问我，后续直接执行即可"

## 选项

| 选项 | 优点 | 缺点/代价 |
|---|---|---|
| A. 每次补测试都先询问 | 用户完全控制工作量 | 低风险动作也要等回复，打断节奏 |
| B. 补测试默认授权，但改实现仍需决策（本次采用） | 补测不再阻塞；行为变更仍受 D-0002 约束 | Agent 需要自律区分"补测"与"顺手改实现" |

## 决定

- **D-0007-01**：为**已实现行为**补测试（不改行为、不改接口）属于默认授权，Agent **直接执行，不再询问**。
- **D-0007-02**：补测试仍须满足既有质量门禁：`gofmt` / `go vet` / `staticcheck` / `go test` 全绿，提交类型用 `test`。
- **D-0007-03**：补了哪些用例必须落盘（任务记录或 STATUS 的「最近验证」），便于后续会话判断覆盖范围。
- **D-0007-04**：若补测试过程中**发现缺陷需要改实现**，回到 [D-0002](D-0002-decision-gate.md) 门禁：先给决策表格，不擅自改行为。
- **D-0007-05**：不因"补测试"扩大范围（例如顺手重构被测代码）；范围扩散仍按 §1.4 处理。

## 理由

- 补测试是纯收益、低风险、可回滚的动作，等待确认的沟通成本高于风险本身。
- 但"补测试"与"改实现"必须划清界限：前者是验证，后者会改变行为，仍然需要用户拍板（D-0002）。
- 要求落盘覆盖范围，是因为测试的价值取决于"测了什么、没测什么"是否可追溯。

## 影响面

- **流程**：Agent 可以自主补测；用户不再收到"要不要补测试"的询问。
- **代码**：只增加测试文件与用例，不改生产代码。
- **文档**：AGENTS.md 新增 §1.13；本决策与索引、STATUS 同步。
- **安全/成本**：无。

## 回滚方式

删除 AGENTS.md §1.13 与本决策，恢复"补测试前先询问"的流程。
