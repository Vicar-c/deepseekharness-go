# D-0006 · 用户的学习注释不进提交

- **状态**：生效
- **日期**：2026-11-21
- **决策人**：用户
- **关联任务**：—（规则类决策，无独立任务）
- **关联提交**：`docs` 提交（AGENTS.md §1.12 与例外说明）
- **取代/被取代**：—

## 背景

用户在阅读源码时会在代码里写**中文学习注释**（例如解释 `context.Background()` 与 `context.WithTimeout` 的关系、`context.WithoutCancel` 为什么不能取消）。这些注释是用户自己看的笔记，不属于交付物。

此前工作区里 `cmd/dsh/main.go` 与 `internal/kernel/kernel.go` 各自出现 6 行这样的未提交注释，与 AGENTS.md 中"提交前 `git status` 必须干净"的要求相冲突。用户明确指示：

> "我的中文 diff 不需要提交，这是我自己用的，记住（写到记忆文件内），以后这种中文注释都不需要"

## 选项

| 选项 | 优点 | 缺点/代价 |
|---|---|---|
| A. 把用户注释一起提交（原规则） | 工作区永远干净 | 污染提交历史，把私人笔记变成公开仓库内容；与 §1.9"代码用英文"冲突 |
| B. 让用户把注释写在仓库外 | 仓库零污染 | 失去"在代码旁标注"的学习体验，且已经写下的注释要搬家 |
| C. 允许工作区保留用户注释，Agent 只提交自己显式添加的路径（本次采用） | 保护用户笔记；提交历史干净；规则可机械执行（禁用 `git add -A`） | "工作区必须干净"的质量门禁需要一个明确例外，且依赖 Agent 严格用显式路径 |

## 决定

- **D-0006-01**：用户写在代码里的中文学习注释**不提交、不还原、不删除**，也不为其补测试或"润色"。
- **D-0006-02**：由这些注释造成的未提交文件属于**正常状态**；`git status` 的干净要求（§1.8、§4、§6、§11）以此为唯一例外。
- **D-0006-03**：Agent 提交**必须显式列路径**（`git add <file> ...`），**禁止** `git add -A`、`git add .`、`git commit -a`、`git stash`、`git checkout -- .`。
- **D-0006-04**：Agent 自己写代码仍遵守 §1.9：注释用英文；不写中文注释，也不翻译/改写用户的中文注释。
- **D-0006-05**：改动用户注释所在的文件时，保留用户注释；确实冲突时在任务记录中说明处理方式。

## 理由

- 公开仓库的提交历史应只包含交付物；个人笔记进历史后无法干净移除（需要改写历史）。
- 用户的注释是学习过程的一部分，强行规范化会破坏其使用价值。
- 用"显式路径提交"而不是"约定别提交"来落地，是因为前者可以被机械检查（命令层面禁用），后者依赖每次自觉。

## 影响面

- **流程**：Agent 提交方式收紧为显式路径；预检/DoD/结束清单的"干净"判断增加例外说明。
- **代码/数据**：无。用户注释不进入任何提交，仓库内容不变。
- **文档**：AGENTS.md 新增 §1.12，并修订 §1.8、§4、§6、§11 四处措辞；本决策与索引、STATUS 同步。
- **安全/成本**：无。

## 回滚方式

删除 AGENTS.md §1.12 与四处例外说明、删除本决策；恢复"提交前工作区必须完全干净"的旧规则。
