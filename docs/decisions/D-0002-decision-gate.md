# D-0002 · 会话内决策表格与实施门禁

- **状态**：生效
- **日期**：2026-11-16
- **决策人**：用户
- **关联任务**：[T-0003](../tasks/T-0003-decision-gate.md)
- **关联提交**：docs 提交（决策门禁规则）
- **取代/被取代**：—

## 背景

此前待用户决策的事项只写入 `docs/STATUS.md`，用户需要到文档里翻找；决策与实施之间也没有硬边界。用户明确要求：

> "你的询问不仅仅放到文档里，最好每次都在会话内列好表格，我一一决策，没决策完时不要去实现，只有我说实现再去实现。"

## 选项

| 选项 | 优点 | 缺点/代价 |
|---|---|---|
| A. 仅文档记录 | 不打扰会话 | 用户需翻文档，易漏决策 |
| B. 会话内表格 + 实施门禁（逐项决策 + 明确"实现"授权） | 决策可见、边界清晰、可追溯 | 每轮需维护表格 |
| C. 不设门禁，边决策边实施 | 速度快 | 容易在未确认时做错方向 |

## 决定

- **D-0002-01**：所有待用户拍板的问题，必须在会话回复中以编号表格呈现（ID、问题、选项、建议、影响），并与 `docs/STATUS.md`「决策队列」同源。
- **D-0002-02**：用户逐项决策；**存在未决项时禁止开始实施**，相关任务保持 `todo`/`blocked`。
- **D-0002-03**：只有用户明确说"实现"（或等价明确授权）后才进入实施；**逐项批准决策 ≠ 实施授权**。
- **D-0002-04**：每轮回复若仍有未决项，末尾保留最新决策表格（已决项标注结论），直至全部决策完成或用户撤销。
- **D-0002-05**：决策完成后写入决策记录与任务记录，决策队列标记 `resolved`，再按 D-0001 的质量门禁实施。
- **D-0002-06**：代理不得把"未答复"视为"默认同意"；用户未答复即视为未决策。

## 理由

- 让决策在会话中可见、可逐项勾选，降低沟通成本与漏项风险。
- 硬性实施门禁避免"边问边做"导致的返工与范围漂移，符合用户"只做需求内"的原则。
- 决策表格与 STATUS 队列同源，保证跨会话接力时不丢失决策上下文。

## 影响面

- 流程：每个任务可能有"决策表格 → 逐项决策 → 用户说实现 → 实施"的等待期。
- 文档：`docs/STATUS.md` 新增「决策队列」；每轮回复末尾维护表格。
- 代码：无直接影响；实施阶段仍遵循既有质量门禁。
- 安全/成本：无。

## 回滚方式

删除本决策并在 AGENTS.md §1.11、WORKFLOW §3.4、STATUS 决策队列中移除该规则；恢复"决策仅文档记录、可边决策边实施"的旧流程。
