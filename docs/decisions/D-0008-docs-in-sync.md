# D-0008 · 文档必须随实现并行更新

- **状态**：生效
- **日期**：2026-11-21
- **类型**：用户规则类决策（工作方式）
- **关联**：[AGENTS.md](../../AGENTS.md) §1.14、§6；[cmd/dsh/docs_test.go](../../cmd/dsh/docs_test.go)；[T-0016](../tasks/T-0016-gap-audit.md)

## 背景

2026-11-21 的差距审计发现：`README.md` 从 P0 之后就再没跟上——它仍在描述"meta 行 + message 行"的旧会话格式、只有 5 个工具、`internal/builtin` 只有 fs/shell/time、"尚未迁移 edit/glob/grep/todo"，而实际这些在批次 0–4 中早已实现（v4 事件流、11 个工具、流式、profiles、工具批次并发）。

用户的原话：

> 像是文档相关这种应该要根据我们实现的进度并行更新才对，不能一直不更新

这说明问题不是"某次忘了改 README"，而是**流程里没有把文档当成增量的一部分**：AGENTS.md 只在"会话结束前"要求更新 `docs/STATUS.md` 与任务记录，对面向使用者的 README / 架构 / 迁移映射没有强绑定，于是它们自然滞后。

## 选项

| 选项 | 含义 | 代价 |
|---|---|---|
| A. 每个增量同批更新文档（选定） | 改了用户可见行为，就在同一批提交里改对应文档；每批收尾跑文档检查 | 每批多花几分钟；提交更完整 |
| B. 保持现状（会话结束前统一补） | 少改几次文档 | 长期滞后（已发生）；下个会话读到的是错的；新读者被误导 |
| C. 只靠人工提醒 | 在报告里写"记得更新文档" | 不具约束力，事实已证明会失效 |

## 决定

**A：文档随实现并行更新，且关键事实由测试强制。**

1. **同批更新**：任何用户可见的增量（CLI 命令/flag、工具增删、会话格式、配置项与默认值、profile/bundle、能力开关、安全边界）必须在同一批提交内更新对应文档，不得登记成"遗留"。
2. **对应关系**写入 [AGENTS.md](../../AGENTS.md) §1.14 的表格：README / ARCHITECTURE / MIGRATION_MAP / STATUS / 任务记录各自负责哪些改动。
3. **README 的三块内容由测试钉死**：`cmd/dsh/docs_test.go` 校验
   - 命令清单 = `main.go` 的子命令 switch = usage 文本；
   - 工具表 = 实际注册的工具（含 `pwsh`/`bash` 双拼写）；
   - 配置示例键集合 = `config.Fields()`，且示例能被 `config.Config` 反序列化（未知字段即失败）。
4. **质量门禁加入文档**：每批收尾跑 `go test ./cmd/dsh` 与 `scripts/check_md_links.py`；CI 增加 Markdown 相对链接校验。

## 理由

- 文档是跨会话记忆的载体（AGENTS.md §1.1/§1.3）。滞后的 README 会**主动误导**下一个会话与外部读者，比没有文档更糟。
- 只有可执行的检查才有约束力：把命令/工具/配置三块钉成测试后，"改了代码忘了改文档"会直接让 CI 红，而不是靠自觉。
- 改动与文档同批提交，diff 里能直接看到"行为变了、说明也变了"，评审成本最低。

## 影响

- `cmd/dsh` 从 0% 覆盖率变成有 3 个文档契约用例（顺带补上了差距审计 D3 的一半）。
- 以后**新增**工具、命令、配置项时必须同时改 README，否则 `go test ./...` 失败。
- 架构/迁移映射没有自动检查，仍靠 §1.14 的表格与批次收尾清单约束。

## 回滚方式

删除 `cmd/dsh/docs_test.go` 与 AGENTS.md §1.14 即可回到"人工维护文档"；`D-0008` 记录保留（只追加不覆盖）。
