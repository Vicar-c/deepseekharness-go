# D-0001 · 项目总体基调与协作原则

- **状态**：生效（其中 D-0001-06 起的代理推导基调待用户确认/可修订）
- **日期**：2026-11-16
- **决策人**：用户（D-0001-01…05）；代理（D-0001-06…11，用户委托"可以针对我的风格再确定一些项目实现的总体基调"）
- **关联任务**：[T-0002](../tasks/T-0002-agent-guidelines.md)
- **关联提交**：docs 提交（协作契约与记录体系）
- **取代/被取代**：—

## 背景

项目由用户发起并长期迭代，需要跨多个会话、可能由多个 Agent 协作完成。用户明确要求：

1. 任何决策/实现都必须落盘详细的 Markdown，方便跨会话任务；
2. 用户自己的决策要有单独记录文件，并以任务为维度建立文件；
3. 任务过大时要适时驱动多 Agent 实现；
4. 不要做无意义重构，但旧逻辑存在性能/实现问题时要大胆重构；
5. 仅针对需求实现内容，不要过度扩散；有扩散的地方需要用户决策；
6. 其余项目实现总体基调由代理结合用户风格推导。

## 决定

### 用户决策（原始需求，直接生效）

- **D-0001-01**：任何决策/实现必须落盘详细 Markdown（任务记录 + 决策记录），作为跨会话记忆。
- **D-0001-02**：用户决策单独建立记录文件，以任务为维度组织；只追加、不覆盖。
- **D-0001-03**：任务过大时适时驱动多 Agent 实现；需明确写作用域、任务板与验收。
- **D-0001-04**：禁止无意义重构；但性能/正确性/可维护性存在证据时，鼓励大胆重构（单独提交、有测试、行为保持）。
- **D-0001-05**：仅实现需求内内容；范围扩散必须记录并交由用户决策。

### 代理推导的项目基调（用户委托，默认生效，可修订）

- **D-0001-06**：结果导向——交付必须能运行、能验证、能复现。
- **D-0001-07**：证据驱动——性能/重构/兼容性结论须有测量或测试支撑；报告附命令与结果。
- **D-0001-08**：文档即记忆——会话是工作区，落盘文档是唯一可靠记忆；STATUS 每次会话更新。
- **D-0001-09**：稳定优先——技术选型优先成熟稳定；新依赖/新方案需理由、收益与回滚路径。
- **D-0001-10**：执行彻底——装环境要验证、构建要真跑、API 要真调、文档要落地。
- **D-0001-11**：隔离与最小权限——密钥仅环境变量；数据目录与既有 DSH 安装隔离（`~/.deekseekharness-go` vs `~/.dsh`）。
- **D-0001-12**：小步提交——一个可验证增量一个 commit；规范见 AGENTS.md §7。
- **D-0001-13**：中文文档、英文代码标识符与 commit。
- **D-0001-14**：人类保留最终决策权——范围、安全、成本、产品交互、破坏性变更不由 Agent 代拍。

## 选项（为什么不是别的）

| 选项 | 优点 | 缺点/代价 | 结论 |
|---|---|---|---|
| A. 只靠会话记忆 + git log | 成本最低 | 跨会话丢失上下文，决策不可追溯 | 否决 |
| B. 单一巨型文档记录一切 | 集中 | 冲突、膨胀、难维护 | 否决 |
| C. 按任务拆分任务记录 + 决策记录 + 状态快照 | 可追溯、并行友好、低冲突 | 需要每次会话维护文档 | **采用** |

## 理由

- 用户明确要求跨会话可接力，且项目会长期迭代、可能多 Agent 并行，记录体系是唯一可靠载体。
- 任务维度拆分与多 Agent 写作用域天然契合，能减少冲突。
- 用户决策与实现记录分离，既满足"单独决策文件"，也避免实现细节淹没决策。

## 影响面

- 代码：无行为影响。
- 流程：每个任务需要登记记录、每次会话需更新 `docs/STATUS.md`。
- 安全：密钥仅环境变量；记录中不得出现明文密钥。
- 兼容性：无。

删除本决策与对应任务记录，恢复为"仅 git log"模式；或修订 D-0001-06…14（用户可直接否决任意一条，代理更新本文件与 AGENTS.md §9）。
